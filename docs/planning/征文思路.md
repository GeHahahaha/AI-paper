# “人工智能+”金融科技创新应用大赛案例思路

## 当前申报方向

本案例描述一套由本所自主设计和掌控的 AI 研发工作流：以 **Pi 为智能执行中枢和节点运行时**，通过多个专业 Agent 覆盖需求、设计、开发、测试、审查、交付和运行反馈；以 **MCP Bridge 或内部连接器为受控外部交互层**，连接项目、知识、代码、测试、质量、发布与运维平台；正式项目状态和审批结论仍由既有研发平台保存，人工保留目标确认、关键方案、核心代码合并、生产发布和异常处置责任。

旧的“Qoder + TDD 改造无人维护遗留系统”单一工具叙事已归档，不再作为正文主线；机构投票存量项目保留为已经完成项目级闭环验证的核心实践案例，但不用于定义整套 Pi + MCP 平台架构。

## 推荐题目

**首选题目：**

> 从单点辅助到可信协同：基于 Pi 与 MCP 的金融科技 AI 研发工作流设计与实践

**备选题目：**

1. 让研发过程可理解、可验证、可审计：金融研发 AI 工作流创新实践
2. Pi 驱动、MCP 连接：面向金融研发全生命周期的可信协同体系
3. 可执行、可管控、可评价：金融机构自主 AI 研发工作流实践

## 一句话价值

项目将 AI 从分散的编码助手升级为受治理的研发执行体系：Pi 在任务级上下文中自主完成规划、实施、验证、审查和复盘，MCP 在最小权限和全程审计下连接既有研发平台，人工在关键风险节点作出决策，形成可执行、可验证、可追溯、可持续改进的金融科技研发闭环。

## 核心叙事

文章应回答：

> 如何在不替换既有研发平台、不放弃人工责任和安全边界的前提下，让 AI 从单点辅助工具变成能够承接完整研发任务的可信协同体系？

围绕三个层次展开：

1. **Pi 智能执行**：主控 Agent 维护单个智能任务的执行状态，组织需求、架构、编码、测试、审查、发布和运维 Agent，处理规划、执行、校验、失败修复与结果汇总。
2. **MCP 受控连接**：通过 MCP Bridge、Extension 或内部连接器统一工具发现、结构化上下文、参数校验、最小权限、凭据托管、读写白名单、审计留痕和状态回写。
3. **人机责任与治理**：低风险任务按策略自动推进；高风险需求、关键方案、核心代码合并、生产发布、异常终止和回滚由授权人员确认。

成熟度表达统一为：基础能力已经投入使用，机构投票案例已经完成项目级闭环验证，Pi + MCP 总体方案正在平台化和跨项目复制。平台化尚在推进不等于案例没有形成闭环。

## 正文建议结构

### 1. 应用背景：为什么单点 AI 工具无法形成组织效能

- AI 已进入代码生成、测试和审查等环节，但入口分散、上下文割裂、规则不一致。
- 研发人员仍需在项目、代码、测试和发布平台之间反复搬运信息，AI 产物缺少连续状态和统一证据。
- Agent 获得代码、终端和平台权限后，数据泄露、工具滥用、错误执行和责任不清等风险随之扩大。
- 项目目标不是追求“无人研发”，而是建设能接入既有体系、按风险自主运行并接受治理的研发执行能力。

### 2. 总体方案：Pi 中枢、MCP 总线、人工检查点

这一节使用《图5_AI增强研发全生命周期总图.drawio》作为主图，先用传统的任务受理、需求、设计、开发、测试、审查验收、发布交付和运行反馈建立主轴，再说明 Pi、MCP 与人工责任如何贯穿主轴：

- 研发交付闭环：任务 → 认知 → 设计 → 规划 → 实施 → 验证 → 审查 → 交付 → 运行反馈。
- 能力运营闭环：运行记录 → 真实任务评价 → 失败复盘 → 知识/Skill/Rule/流程更新 → 再验证 → 推广或退出。

### 3. 全流程实施：九个阶段

1. 任务受理与风险分级。
2. 上下文构建与项目认知。
3. 需求澄清与方案设计。
4. 任务规划与 Agent 编排。
5. 隔离环境实施。
6. 自动验证与失败修复。
7. 独立审查与整改。
8. 人工审批与受控交付。
9. 运行观察与持续学习。

每个阶段都按“输入—Pi 动作—MCP 交互—校验条件—人工责任—输出证据”六项说明，避免写成抽象概念或工具清单。

### 4. 自主可控的技术与治理机制

- 流程、知识、Skill、Rule、评价任务和审计记录由本方管理。
- 模型通过路由层调用，可以按敏感等级、能力、成本和稳定性替换。
- 源码、数据和执行环境按分类分级放在自建或专属受控环境。
- 外部系统凭据由 MCP 连接层或既有凭据系统托管，Pi 不直接持有长期高权限凭据。
- 高风险操作设置人工审批、操作白名单、限时权限、沙箱和资源限制。
- AI 产物必须经过自动测试、独立审查和证据汇总后才能进入人工交付检查点。

### 5. 实施效果：证明工作流完成了真实任务

建议使用真实、脱敏的研发任务建立基线和对照，至少统计：

- 任务完成率、一次通过率、失败和人工接管分布。
- 需求到交付的周期、等待时间及人工投入变化。
- 测试通过率、覆盖率、缺陷发现和线上回归情况。
- AI 审查有效问题数、采纳率和高风险问题拦截情况。
- MCP 调用成功率、权限拒绝、越界拦截和异常恢复情况。
- 单任务模型与算力成本，以及知识、Skill、Rule 的复用次数。

不以代码生成率、调用次数或生成代码行数替代真实交付成效。

### 6. 风险控制：金融研发场景的责任边界

- 数据边界：分类分级、脱敏、上下文最小化和外发限制。
- 权限边界：身份映射、最小权限、限时授权和高风险操作审批。
- 执行边界：隔离分支、安全沙箱、网络白名单、资源限额和禁止事项。
- 质量边界：明确验收条件、质量阈值、独立审查和证据化交付。
- 责任边界：核心合并、生产发布、生产数据和权限变更由授权人员决策。
- 运营边界：全过程留痕、可回放、真实任务评价、异常降级和能力退出。

### 7. 推广价值：形成组织级研发能力资产

结尾不要停留在“一次任务提效”，而要说明经过验证的知识、Skill、Rule、流程模板、连接器和评价任务可以复用到更多项目。系统价值是把个人使用 AI 的经验转化为组织可管理、可复制、可审计、可持续优化的研发能力。
