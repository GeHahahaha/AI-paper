# Pi + MCP 自主可控 AI 研发工作流设计

## 核心定位

本方案不再描述若干 AI 工具分别接入研发环节，而是建设一套以 **Pi 为自主研发执行中枢、MCP 为外部系统受控交互层** 的端到端工作流。

- **Pi 负责“想和做”**：作为智能执行中枢和节点运行时，理解任务、组织上下文、规划拆解、调度专业 Agent、生成研发产物、运行验证、处理失败并汇总交付证据。
- **MCP 负责“连和管”**：连接项目、知识、代码、测试、质量、发布和运维系统，执行工具发现、参数校验、权限控制、凭据托管、调用留痕和状态回写。
- **人负责“定和批”**：确定目标与验收标准，对高风险需求和方案作出确认，审批核心代码合并与生产发布，处理异常、回滚及责任事项。

“自主可控”不等于无人参与，而是流程、知识、规则、数据、执行环境和审计记录由本方掌控；模型与工具可替换；AI 自主程度与任务风险匹配。

既有项目管理、代码、测试和发布平台继续保存正式任务状态、审批结论和责任关系。Pi 维护单个智能任务的执行上下文和步骤状态，不替代正式研发管理系统；MCP Bridge、Extension 或内部连接器负责将批准的外部能力映射为 Pi 可调用工具。

当前整体研发流程已经贯通并支持任务回放，MCP 已连接 Git、ONES、Jira 等研发平台；代码审核平台通过 MCP 获取 Git 提交差异，并支持定时全量扫描。流程贯通情况已经确认，但各执行阶段的长期稳定性仍需通过成功率、失败类型、人工介入和运行周期等指标量化。

正式申报稿暂不公开 Pi、MCP、Harness、模型、业务系统及其他内部平台真实名称，分别使用“智能执行中枢”“受控连接层”“多智能体质量门禁工作流”和“某存量金融业务系统”等功能性匿名名称。

## 端到端主流程

1. **任务受理与风险分级**：解析目标、范围和验收标准，识别数据、权限和执行风险，形成任务契约与审批策略。
2. **上下文构建与项目认知**：通过 MCP 按需获取需求、代码、历史变更、测试结果和运行信息，建立任务级上下文并识别信息缺口。
3. **需求澄清与方案设计**：生成验收条件，完成影响分析、架构设计、接口与数据设计；高风险或语义不明确事项进入人工确认。
4. **任务规划与 Agent 编排**：拆解可执行步骤，选择需求、架构、编码、测试、审查、发布或运维 Agent，配置模型、工具、依赖和检查点。
5. **隔离环境实施**：在受控分支和沙箱中修改代码、配置和文档，保持小步提交，并记录决策依据。
6. **自动验证与失败修复**：运行单元测试、集成测试、静态检查和安全检查；失败时自动归因、修复和复测，直至达标或触发人工介入。
7. **独立审查与整改**：使用独立上下文和审查 Agent 检查正确性、安全性、合规性、可维护性及变更影响；问题返回设计或实施环节。
8. **人工审批与受控交付**：生成 PR、变更说明、测试证据、风险清单、发布与回滚方案；授权人员审批合并和生产发布，MCP 仅在授权后触发现有流水线。
9. **运行观察与持续学习**：获取健康检查、日志、指标和告警，辅助异常归因与处置；任务完成后复盘并沉淀知识、Skill、Rule、流程模板和评价任务。

## 统一节点契约与确定性门禁

每个可复用研发节点统一表达为：

> 节点 = 输入工件 + Agent 角色 + Skill/Rule + 工具白名单 + 结构化输出 + 确定性校验 + 人工审批 + 审计证据 + 成功/返工路由

- 生成式 AI 负责分析、生成和解释，编译、测试、覆盖率、扫描及其他强制门禁由确定性程序判定。
- 节点必须明确正式产物、质量阈值、人工责任人和失败去向，不能仅以模型自行判断“已完成”作为流转依据。
- 失败后根据原因返回需求、设计、开发或测试节点，不简单从头重跑。
- 超过重试阈值、连续失败、信息不足或风险升级时，转人工接管并决定继续、降级或终止。

### 结构化交接

- 需求、设计、开发、测试和审查 Agent 使用职责隔离的任务会话，不依赖同一段完整对话历史持续传递。
- 上下游只通过受控的结构化交付物交接，包括需求规格、实施计划、代码差异、测试报告、审查结论和交付证据。
- 每份交付物标明输入来源、任务范围、版本、输出格式、完成条件和人工确认状态。
- 长任务保留节点状态、交付物和检查点，以便中断后恢复、复盘和回放；恢复能力按实际运行证据评价。

### 证据驱动的完成条件

节点完成不能只依据模型声明，必须同时具备：

- 与任务目标对应的代码、测试、配置或文档变更。
- 关键工具调用、执行结果和异常处置记录。
- 可复现并达到任务契约门禁的编译、测试、覆盖率或扫描结果。
- 独立审查结论、阻断问题处置结果和必要的人工审批或验收状态。

## Pi 内部能力

- 主控 Agent：维护智能任务内部执行状态，完成流程编排、检查点控制、异常处理和结果汇总；正式项目状态和审批结论仍以既有研发平台为准。
- 专业 Agent：需求、架构、编码、测试、审查、发布和运维分析。
- 共享任务状态：任务契约、上下文、计划、产物、证据和决策记录。
- 策略与风险引擎：任务分级、工具白名单、审批规则、质量阈值和降级策略。
- 模型路由：按任务能力、敏感等级、成本和稳定性选择可替换模型。
- 可观测与评价：记录成功率、失败类型、人工投入、质量、安全、成本和运行时延。

## MCP 交互边界

所有外部系统交互原则上通过受控 MCP Bridge、Extension 或内部连接器完成，Pi 不直接保存外部系统凭据，也不绕过既有权限和审批体系。MCP 在本方案中是外部能力的连接与治理机制，不被描述为 Pi 原生提供的完整工作流系统。

- 项目与知识：需求、任务、制度、架构、历史记录。
- 代码仓库：代码读取、分支、提交、PR 和审查状态。
- 测试与 CI：构建、测试、覆盖率、制品和执行结果。
- 质量与安全：静态扫描、依赖检查、漏洞及合规规则。
- 发布平台：发布申请、审批状态、制品部署和回滚。
- 运维观测：日志、指标、链路、告警、事件和工单。

MCP 层统一实施工具发现、结构化上下文、参数校验、最小权限和限时授权、读写白名单、凭据托管、调用审计、结果标准化与状态回写。

## 贯穿式控制

- 数据边界：分类分级、脱敏、上下文最小化和外发限制。
- 权限边界：身份映射、最小权限、限时授权和高风险操作审批。
- 执行边界：隔离分支、沙箱、网络白名单、资源限额和禁止事项。
- 质量边界：验收条件、测试阈值、独立审查和证据化交付。
- 责任边界：核心合并、生产发布、生产数据和权限变更由授权人员决策。
- 运营边界：全程留痕、可回放、真实任务评价、异常降级和能力退出。
- 供应链边界：Skill、Extension、Package、MCP 连接器及其依赖经过准入审查、版本锁定、漏洞检查，并具备紧急禁用和退出机制。

## 能力成熟度表达

- **已投入使用**：提交触发和定时全量扫描的代码审核能力，以及 Git、ONES、Jira 等平台的受控连接。
- **已完成真实案例闭环**：整系统需求逆向与重构案例已经验收上线；漏洞案例已经完成全机构排查和试点项目整改。
- **已贯通、稳定性待量化**：全流程可以配置 Pi 执行节点，工作流支持过程留痕和回放，但各阶段稳定运行水平仍需统计。

能力成熟度不等同于流程是否闭环。两个案例和整体流程均已有真实执行基础，后续重点是量化稳定性、补充运行证据和扩大跨项目复用。

## 两个闭环

1. **研发交付闭环**：任务 → 认知 → 设计 → 规划 → 实施 → 验证 → 审查 → 交付 → 运行反馈。
2. **能力运营闭环**：运行记录 → 成效评价 → 失败复盘 → 知识/Skill/Rule/流程更新 → 再验证 → 发布或退出。
