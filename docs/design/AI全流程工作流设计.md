# Pi + MCP 自主可控 AI 研发工作流设计

## 核心定位

本方案不再描述若干 AI 工具分别接入研发环节，而是建设一套以 **Pi 为自主研发执行中枢、MCP 为外部系统受控交互层** 的端到端工作流。

- **Pi 负责“想和做”**：理解任务、组织上下文、规划拆解、调度专业 Agent、生成研发产物、运行验证、处理失败并汇总交付证据。
- **MCP 负责“连和管”**：连接项目、知识、代码、测试、质量、发布和运维系统，执行工具发现、参数校验、权限控制、凭据托管、调用留痕和状态回写。
- **人负责“定和批”**：确定目标与验收标准，对高风险需求和方案作出确认，审批核心代码合并与生产发布，处理异常、回滚及责任事项。

“自主可控”不等于无人参与，而是流程、知识、规则、数据、执行环境和审计记录由本方掌控；模型与工具可替换；AI 自主程度与任务风险匹配。

## 端到端主流程

1. **任务受理与风险分级**：解析目标、范围和验收标准，识别数据、权限和执行风险，形成任务契约与审批策略。
2. **上下文构建与项目认知**：通过 MCP 按需获取需求、代码、历史变更、测试结果和运行信息，建立任务级上下文并识别信息缺口。
3. **需求澄清与方案设计**：生成验收条件，完成影响分析、架构设计、接口与数据设计；高风险或语义不明确事项进入人工确认。
4. **任务规划与 Agent 编排**：拆解可执行步骤，选择需求、架构、编码、测试、审查、发布或运维 Agent，配置模型、工具、依赖和检查点。
5. **隔离环境实施**：在受控分支和沙箱中修改代码、配置和文档，保持小步提交，并记录决策依据。
6. **自动验证与失败修复**：运行单元测试、集成测试、静态检查和安全检查；失败时自动归因、修复和复测，直至达标或触发人工介入。
7. **独立审查与整改**：使用独立上下文和审查 Agent 检查正确性、安全性、合规性、可维护性及变更影响；问题返回设计或实施环节。
8. **人工审批与受控交付**：生成 PR、变更说明、测试证据、风险清单、发布与回滚方案；授权人员审批合并和生产发布，MCP 仅在授权后触发现有流水线。
9. **运行观察与持续学习**：获取健康检查、日志、指标和告警，辅助异常归因与处置；任务完成后复盘并沉淀知识、Skill、Rule、流程模板和评价任务。

## Pi 内部能力

- 主控 Agent：任务状态机、流程编排、检查点控制、异常处理和结果汇总。
- 专业 Agent：需求、架构、编码、测试、审查、发布和运维分析。
- 共享任务状态：任务契约、上下文、计划、产物、证据和决策记录。
- 策略与风险引擎：任务分级、工具白名单、审批规则、质量阈值和降级策略。
- 模型路由：按任务能力、敏感等级、成本和稳定性选择可替换模型。
- 可观测与评价：记录成功率、失败类型、人工投入、质量、安全、成本和运行时延。

## MCP 交互边界

所有外部系统交互原则上通过 MCP 连接器完成，Pi 不直接保存外部系统凭据，也不绕过既有权限和审批体系。

- 项目与知识：需求、任务、制度、架构、历史记录。
- 代码仓库：代码读取、分支、提交、PR 和审查状态。
- 测试与 CI：构建、测试、覆盖率、制品和执行结果。
- 质量与安全：静态扫描、依赖检查、漏洞及合规规则。
- 发布平台：发布申请、审批状态、制品部署和回滚。
- 运维观测：日志、指标、链路、告警、事件和工单。

MCP 层统一实施工具发现、结构化上下文、参数校验、最小权限和限时授权、读写白名单、凭据托管、调用审计、结果标准化与状态回写。

## 贯穿式控制

- 数据边界：分类分级、脱敏、上下文最小化和外发限制。
- 权限边界：身份映射、最小权限、限时授权和高风险操作审批。
- 执行边界：隔离分支、沙箱、网络白名单、资源限额和禁止事项。
- 质量边界：验收条件、测试阈值、独立审查和证据化交付。
- 责任边界：核心合并、生产发布、生产数据和权限变更由授权人员决策。
- 运营边界：全程留痕、可回放、真实任务评价、异常降级和能力退出。

## 两个闭环

1. **研发交付闭环**：任务 → 认知 → 设计 → 规划 → 实施 → 验证 → 审查 → 交付 → 运行反馈。
2. **能力运营闭环**：运行记录 → 成效评价 → 失败复盘 → 知识/Skill/Rule/流程更新 → 再验证 → 发布或退出。
